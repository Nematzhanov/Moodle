# CodeCheck — детектор ИИ-кода

Программа оценивает вероятность того, что код на C++ или Java написан нейросетью, а не человеком. В основе модель `microsoft/codebert-base` (Microsoft, лицензия MIT), дообученная на размеченных примерах «человек / ИИ». Для каждого языка обучается отдельная модель. Результат служит подсказкой для преподавателя и не является доказательством.

## 2. Как устроен процесс

1. **Исходные данные** лежат в `data/sources/`. Каждый файл — CSV с колонками `code;label` (разделитель `;`), где `label = 0` означает код человека, `1` — код ИИ.
2. **Сборка выборок.** Скрипты `tools/regenerate_*_split.py` делят исходные данные на обучающую и тестовую выборки и записывают их в `data/train/`.
3. **Проверка.** `tools/check_datasets.py` ищет дубли, противоречивую разметку и пересечения между train и test.
4. **Обучение.** `src/train.py` дообучает CodeBERT на `data/train/` и сохраняет модели в `models/<язык>/`.
5. **Проверка кода.** `src/detect.py` загружает модель нужного языка и выдаёт вероятность ИИ-авторства.

## 3. Код

### src/train.py — обучение

Для каждого языка выполняются одни и те же шаги.

**Подготовка данных.** `read_csv_auto` читает CSV с запятой или точкой с запятой, исправляет опечатку `lable` в заголовке и удаляет дубли кода. От обучающей выборки отрезается 10% под валидацию (стратифицированно по классам). По валидации выбирается лучшая эпоха, а тестовая выборка проверяется один раз в конце. Если выбирать эпоху по тесту, оценка на тесте получается завышенной.

**Токенизация.** Класс `CodeDataset` токенизирует все примеры один раз при создании и обрезает их до 512 токенов: это предел CodeBERT. `PadCollator` дополняет примеры паддингом только до длины самого длинного в батче, а не до 512, поэтому короткие файлы обрабатываются быстрее.

**Модель.** `AutoModelForSequenceClassification` добавляет к CodeBERT классификатор на два класса. Дообучается вся сеть, а не только классификатор.

**Функция потерь.** Используется перекрёстная энтропия с весами классов `n / (2 · n_класса)`. Веса нужны, потому что выборка C++ несбалансирована: 935 примеров «человек» и 408 «ИИ». Без весов модель смещалась бы к большему классу.

**Оптимизация.** AdamW (lr 2e-5, weight decay 0.01), линейный разогрев learning rate на первых 10% шагов, затем линейное снижение, ограничение нормы градиента 1.0.

**Устройство.** `pick_device` выбирает CUDA, затем Apple Silicon (MPS), затем CPU. Параметры зависят от устройства:

| устройство | батч | аккумуляция | смешанная точность |
|---|---|---|---|
| NVIDIA (CUDA) | 16 | 1 | bf16 на картах Ampere и новее, fp16 на старых |
| Apple Silicon (MPS) | 2 | 3 | нет |
| CPU | 8 | 1 | нет |

На Mac память общая у GPU и системы, поэтому батч маленький, а эффективный размер 6 набирается аккумуляцией градиента. Для fp16 используется `GradScaler`, для bf16 он не нужен. На CUDA дополнительно включается TF32.

**Результат.** Веса лучшей эпохи хранятся в памяти на CPU и восстанавливаются перед сохранением. В папку модели записываются веса, токенизатор и `metrics.json` (точность на валидации, тесте и OOD-тесте, размеры выборок, устройство). OOD-тест — выборка из генераторов и источников, которых не было в обучении. Он есть только у датасетов из `data/pending/`.

Параметры командной строки: `--lang`, `--device`, `--epochs`, `--batch-size`, `--grad-accum`, `--eval-batch-size`, `--workers`, `--lr`, `--max-length`, `--no-amp`, `--max-train` (урезать выборку для быстрой проверки). Пути можно переопределить переменными окружения `CODECHECK_ROOT`, `CODECHECK_DATA_DIR`, `CODECHECK_MODELS_DIR`. Так работает Docker.

### src/detect.py — проверка кода

Загружает модели из `models/cpp` и `models/java`, токенизирует код (до 512 токенов) и переводит выход модели в вероятности функцией softmax. Вывод:

| вероятность ИИ | вердикт |
|---|---|
| 80% и выше | почти точно написан ИИ |
| 60–79% | скорее всего ИИ |
| 40–59% | сложно определить |
| 20–39% | скорее всего человек |
| ниже 20% | почти точно написан человеком |

Два режима. Интерактивный: выбрать язык (`cpp` или `java`), вставить код, на отдельной строке ввести `END`. Одной командой: `--lang cpp --file путь`. Маркер `END` нужен потому, что в коде бывают пустые строки, и окончание ввода по пустой строке обрывало вставку.

### src/cpp_checker.py — терминальное приложение для C++

Полноэкранное приложение в терминале на библиотеке Textual. Слева редактор с номерами строк и подсветкой C++ (грамматика tree-sitter), справа результат: вероятность ИИ крупными цифрами, шкала, вердикт, подробности и история проверок за сеанс.

Проверка запускается двойным Enter (два нажатия быстрее 0,45 с) или клавишей F5. Первый Enter вставляет перевод строки, второй не вставляет ничего. Вставка кода через буфер обмена проверку не запускает. Другие клавиши: Ctrl+O открыть файл, Ctrl+L очистить, Ctrl+Q выход.

В отличие от `detect.py`, длинный код проверяется целиком. Он режется на фрагменты по 510 токенов с шагом 256, каждый фрагмент оценивается отдельно, итог — среднее. В подробностях показаны пять фрагментов, больше всего похожих на ИИ, с номерами строк. Для кода короче 40 токенов выводится предупреждение о ненадёжной оценке. Если код похож на Java или Python, приложение предупреждает, что модель обучена только на C++.

Модель загружается и код проверяется в фоновом потоке, поэтому интерфейс не зависает. Параметры: `--device` (по умолчанию CUDA → MPS → CPU) и `--model` (папка модели, по умолчанию `models/cpp`).

### src/server.py и src/cpp_model.py — сайт с проверкой C++

`server.py` отдаёт сайт из `website/` и принимает `POST /api/detect` с JSON `{"code": "..."}`. В ответ приходит вероятность ИИ, число токенов, фрагменты с номерами строк и время. `GET /api/health` показывает, подключена ли модель. Сервер написан на стандартном `http.server`, лишних зависимостей нет. Запросы к модели выполняются по одному, размер кода ограничен 512 КБ.

Модель и разбиение на фрагменты вынесены в `cpp_model.py`, им пользуются и сервер, и терминальное приложение, поэтому результаты совпадают.

Сайт сам определяет, есть ли сервер. Если сайт открыт без сервера (файлом или на GitHub Pages), он переходит в демо-режим и пишет об этом.

### src/retrain_java.py, src/retrain_cpp_candidate.py

Импортируют `train.py` и вызывают `train_model` для одного языка. Скрипт для Java перезаписывает `models/java`. Скрипт для C++ сохраняет модель в `models/cpp_candidate`, чтобы новую модель можно было сравнить с рабочей до замены.

### tools/check_datasets.py

Проверяет каждую пару train/test: колонки и метки (только 0 и 1), пустые значения, дубли кода, противоречивую разметку (один и тот же код помечен и как 0, и как 1), утечку между train и test, в том числе после нормализации пробелов, и перекос классов (предупреждение, если меньшего класса меньше 30%). Флаг `--dir data/pending` проверяет новые датасеты до подключения. Код возврата 0 означает, что ошибок нет.

### tools/regenerate_cpp_split.py

Исходник `data/sources/cppdata.csv` (1 013 строк) состоит из двух частей. Первые 293 строки — отдельные примеры. Остальные — пары «оригинальный файл / его переписанный ИИ-вариант», записанные подряд. Скрипт разбивает данные через `GroupShuffleSplit` (80/20): пара всегда целиком попадает в train или в test. Иначе модель видела бы в тесте почти копию обучающего примера.

Дополнительно скрипт:
- выбрасывает тексты с противоречивой разметкой (до удаления дублей, иначе конфликт не виден);
- убирает из train почти-дубли тестовых примеров;
- добавляет в train 568 человеческих решений из `cpp_human_codecontests.csv`, тест не трогает.

Результат: `cpp_train.csv` (1 343 строки), `cpp_test.csv` (214 строк).

### tools/regenerate_java_split.py

База — пары из `javadata.csv` (654 строки), тоже с разбиением по парам. Только в train добавляются очищенные старые выборки (`old_java_*.csv`), 54 ИИ-примера из `java_ai_generated.csv` и копии примеров без строк `package` и `import`. Последнее нужно потому, что без этих копий модель считала ИИ любой фрагмент без шапки файла. Результат: `java_train.csv` (2 483 строки), `java_test.csv` (130 строк).

### tools/fetch_human_cpp_codecontests.py

Скачивает решения на C++ из датасета DeepMind CodeContests через API Hugging Face. Датасет опубликован в феврале 2022 года, до выхода ChatGPT, поэтому решения написаны людьми. Скрипт берёт одно решение средней длины на задачу (80–4 000 символов) и записывает их в `data/sources/cpp_human_codecontests.csv` с меткой 0. Эти примеры нужны, потому что модель путала аккуратный короткий код человека с кодом ИИ.

### tools/make_java_ai_samples.py

Содержит 54 программы на Java, написанные ИИ по типовым учебным задачам, и записывает их в `data/sources/java_ai_generated.csv` с меткой 1.

### tools/build_datasets.py и tools/apply_datasets.py

`build_datasets.py` собирает новые датасеты для Java, Kotlin и C# из открытых наборов на Hugging Face (Rosetta Code, HumanVsAICode, SemEval-2026, CodeMirage, KStack и другие) и записывает их в `data/pending/`. Обработка:
- лицензионные шапки, `package`, служебные комментарии и фразы, выдающие ИИ («as an AI», markdown), удаляются;
- длины кода человека и ИИ выравниваются, чтобы длина не выдавала класс;
- разбиение идёт по задачам;
- отдельно собирается OOD-тест.

Состав и лицензии описаны в `data/pending/DATASET_REPORT.md`. `apply_datasets.py` копирует утверждённые файлы в `data/train/`, сохраняет прежние в `data/backup_<дата>/` и запускает проверку.

### tools/legacy/

Первые версии проекта: загрузка Python-кода (CodeAlpaca против codeparrot). Детекторы C++ и Java эти данные не используют.

## 4. Модели

| модель | обучающая выборка | тест | точность на тесте |
|---|---|---|---|
| `models/cpp` | 775 примеров (до добавления CodeContests) | 214 | 95,3% |
| `models/java` | 2 483 | 130 | 99,2% |

Модели обучены в июле прежней версией скрипта, `metrics.json` у них нет. Тестовые выборки взяты из тех же источников, что и обучающие, поэтому точность на реальных студенческих работах будет ниже. После переобучения C++ на текущей выборке (1 343 примера) цифры изменятся.

## 6. Ограничения

- Модель видит только первые 512 токенов, это примерно 60–100 строк. Остальная часть длинного файла не анализируется.
- Аккуратный короткий человеческий код (олимпиадные шаблоны, учебные алгоритмы) текущая модель C++ относит к ИИ с высокой уверенностью. Решения CodeContests добавлены в выборку для исправления, но модель на ней ещё не переобучена.
- Детектор знает только те стили ИИ, которые были в данных. Код других моделей или вручную изменённый ИИ-код распознаётся хуже.
- Часть датасетов в `data/pending/` (CodeMirage, KExercises) разрешает только некоммерческое использование.
